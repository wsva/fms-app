# Dataset Studio

A standalone Python script collection to initialize, build, and manage dictation datasets. These scripts mirror and extend the pipeline logic embedded in the Tauri desktop app (`src-tauri`), allowing datasets to be built on a server or any machine without the GUI.

---

## What Is a Dataset?

A dataset is a self-contained directory that bundles audio/video media with all the derived artifacts needed for dictation practice: subtitles, waveforms, a SQLite database, and optional reference texts.

```
my_dataset/
├── info.json              # Metadata: name, UUID, version, structure type
├── data.sqlite3           # Populated database (final artifact)
├── media/                 # Source audio/video files
│   ├── lesson_01.mp3
│   └── lesson_02.mp3
├── transcript/            # (Optional) Plain-text transcripts per media file
│   ├── lesson_01.txt
│   └── lesson_02.txt
├── subtitle/              # VTT subtitle files generated by STT model
│   ├── lesson_01.vtt
│   └── lesson_02.vtt
├── waveform/              # Waveform JSON files generated by audiowaveform
│   ├── lesson_01.json
│   └── lesson_02.json
├── book.txt               # (Optional) Full e-book / reference text for alignment
└── README.md              # (Optional) Human-readable notes
```

### info.json

```json
{
    "name": "my_dataset",
    "uuid": "b76a0a93-20e0-4d1a-bd16-ab6f18197952",
    "description": "A short description of this dataset",
    "parent_uuid": "",
    "version": 1,
    "structure": "dictation-v1",
    "updated": "2026-09-08T12:00:00Z"
}
```

## Pipeline Stages

Building a dataset is a multi-stage pipeline. Each stage produces a subset of the final artifacts and can be run independently. Later stages depend on earlier ones.

```
Stage 0 ──► Stage 1 ──► Stage 2 ──► Stage 3 ──► Stage 4
  Init      Media       Subtitles   Database    Alignment
                        Waveforms   (import)    (optional)
```

| Stage | Name | Input | Output | Script |
|-------|------|-------|--------|--------|
| 0 | **Init** | Dataset name, description | Directory structure + `info.json` | `init_dataset.py` |
| 1 | **Media** | Audio/video files (local or downloaded) | Populated `media/` directory | `import_media.py` |
| 2a | **Subtitles** | `media/*.mp3` + STT model | `subtitle/*.vtt` | `generate_subtitles.py` |
| 2b | **Waveforms** | `media/*.mp3` + audiowaveform | `waveform/*.json` | `generate_waveforms.py` |
| 3 | **Database** | `media/`, `subtitle/`, `transcript/` | `data.sqlite3` | `build_database.py` |
| 4a | **Parse Book** | `book.txt` + `data.sqlite3` | `listen_subtitle_reference` rows | `parse_book.py` |
| 4b | **Align Cues** | cues + references in DB | `cue_uuid` links in reference table | `align_cues.py` |
| 4c | **Write Transcripts** | `transcript/*.txt` + DB | `listen_transcript` rows | `write_transcripts.py` |

### Stage Details

**Stage 0 — Init**
Creates the directory skeleton (`media/`, `subtitle/`, `waveform/`, `transcript/`) and writes a fresh `info.json` with a new UUID.

**Stage 1 — Import Media**
Copies or symlinks audio/video files into `media/`. Supports local file paths. For web resources that cannot be downloaded directly, use a browser extension like Web Audio Recorder to capture the audio manually, then place the file in `media/`.

**Stage 2a — Generate Subtitles**
Runs each media file through an STT model (via `transcribe_rs` or a Python-compatible model). Produces one `.vtt` file per media file with sentence-level cues (word-level segments merged on sentence-ending punctuation).

**Stage 2b — Generate Waveforms**
Calls `audiowaveform` (BBC tool) to produce waveform JSON for each media file. These are used by the frontend to render the audio timeline without real-time decoding.

**Stage 3 — Build Database**
Parses all VTT subtitles, media file listings, and optional transcripts into a SQLite database (`data.sqlite3`). Creates the full schema (see below). This is the central data store consumed by the app.

**Stage 4a — Parse Book**
Splits `book.txt` into sentence-sized chunks and inserts them into `listen_subtitle_reference`. These chunks serve as the "ground truth" text for alignment.

**Stage 4b — Align Cues**
Uses dynamic programming to match each subtitle cue to its corresponding reference chunk (from the book or transcript). Writes the `cue_uuid` back into the reference table.

**Stage 4c — Write Transcripts**
Imports plain-text transcript files into the `listen_transcript` table, linked to their corresponding media entry.

## Database Schema

All tables live in a single `data.sqlite3` file per dataset.

```sql
-- Source media files
CREATE TABLE listen_media (
    uuid       TEXT PRIMARY KEY,
    user_id    TEXT NOT NULL,
    title      TEXT NOT NULL,        -- display name (e.g. filename stem)
    source     TEXT NOT NULL,        -- filename or URL to access the file
    note       TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- Full-text transcripts (optional)
CREATE TABLE listen_transcript (
    uuid       TEXT PRIMARY KEY,
    user_id    TEXT NOT NULL,
    media_uuid TEXT NOT NULL,
    transcript TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- STT-generated subtitles (one per media file per model run)
CREATE TABLE listen_subtitle (
    uuid       TEXT PRIMARY KEY,
    user_id    TEXT NOT NULL,
    media_uuid TEXT NOT NULL,
    name       TEXT NOT NULL,        -- model name, date, or label
    note       TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- Individual timed cues within a subtitle
CREATE TABLE listen_subtitle_cue (
    uuid          TEXT PRIMARY KEY,
    subtitle_uuid TEXT NOT NULL,
    order_num     INTEGER NOT NULL,
    start_ms      INTEGER NOT NULL,
    end_ms        INTEGER NOT NULL,
    content       TEXT NOT NULL,
    reference     TEXT                -- matched reference text (after alignment)
);

-- Reference text chunks (from book.txt or transcript)
CREATE TABLE listen_subtitle_reference (
    uuid       TEXT PRIMARY KEY,
    chunk_uuid TEXT NOT NULL,         -- subtitle this reference belongs to
    order_num  INTEGER NOT NULL,
    content    TEXT NOT NULL,
    cue_uuid   TEXT                   -- filled by alignment
);

-- Dictation progress tracking
CREATE TABLE listen_dictation (
    uuid          TEXT PRIMARY KEY,
    user_id       TEXT NOT NULL,
    media_uuid    TEXT NOT NULL,
    subtitle_uuid TEXT NOT NULL,
    status        TEXT NOT NULL DEFAULT '',
    completed     TEXT NOT NULL DEFAULT '',
    created_at    TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at    TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE(user_id, media_uuid, subtitle_uuid)
);
```

## Script Architecture

```
dataset_studio/
├── README.md
├── requirements.txt           # Python dependencies
├── config.py                  # Shared configuration (paths, defaults)
│
├── init_dataset.py            # Stage 0: create directory structure + info.json
├── import_media.py            # Stage 1: copy/link audio files into media/
├── generate_subtitles.py      # Stage 2a: STT → VTT files
├── generate_waveforms.py      # Stage 2b: audiowaveform → JSON files
├── build_database.py          # Stage 3: populate data.sqlite3
├── parse_book.py              # Stage 4a: book.txt → reference chunks
├── align_cues.py              # Stage 4b: DP alignment of cues ↔ references
├── write_transcripts.py       # Stage 4c: transcript files → DB
│
├── lib/                       # Shared library modules
│   ├── __init__.py
│   ├── dataset.py             # Dataset discovery, info.json read/write
│   ├── schema.py              # SQLite schema creation
│   ├── vtt.py                 # VTT parser (timestamp parsing, cue extraction)
│   ├── alignment.py           # DP alignment engine (reusable)
│   └── text.py                # Text normalization, sentence splitting
│
└── tests/                     # Unit tests
    ├── test_vtt.py
    ├── test_alignment.py
    └── test_text.py
```

### Design Principles

1. **One script per stage** — each script is independently runnable and idempotent where possible.
2. **Shared library in `lib/`** — common logic (VTT parsing, alignment, schema) is factored out to avoid duplication.
3. **Dataset path as primary argument** — every script takes the dataset directory path as its first argument, making them composable and scriptable.
4. **No Tauri dependency** — these scripts operate directly on the file system and SQLite, with no dependency on the Rust backend or the frontend.
5. **Compatible with app format** — the output is byte-compatible with what the Tauri app produces, so datasets built here can be used directly by the app.

## External Dependencies

| Tool | Purpose | Required By |
|------|---------|-------------|
| [audiowaveform](https://github.com/bbc/audiowaveform) | Generate waveform JSON from audio | `generate_waveforms.py` |
| STT model (e.g. Whisper via `transcribe_rs` or `faster-whisper`) | Speech-to-text transcription | `generate_subtitles.py` |
| Python 3.10+ | Runtime | All scripts |

## Usage

```bash
# 0. Initialize a new dataset
python init_dataset.py /data/my_dataset --name "My Dataset" --description "..."

# 1. Add media files
python import_media.py /data/my_dataset /path/to/audio_files/

# 2a. Generate subtitles (requires STT model)
python generate_subtitles.py /data/my_dataset --model large-v3

# 2b. Generate waveforms (requires audiowaveform)
python generate_waveforms.py /data/my_dataset

# 3. Build the database
python build_database.py /data/my_dataset

# 4a. Parse book (optional, requires book.txt in dataset dir)
python parse_book.py /data/my_dataset

# 4b. Align cues with references
python align_cues.py /data/my_dataset

# 4c. Import transcripts (optional)
python write_transcripts.py /data/my_dataset
```

## Export from Production

Datasets can also be exported from the FMS website by connecting directly to the production database and extracting the relevant rows. This is a separate workflow not covered by the build pipeline scripts.
